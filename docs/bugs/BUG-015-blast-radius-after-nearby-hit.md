# BUG-015 · 가까운 지점 재폭파 시 반경이 갑자기 커지는 제보

- 제보일:2026-11-08. 상태:압력 범위 수정·빌드/설치 완료·사용자 확인 대기. 실기 장면 재현은 사용자 검증 범위임.
- 관찰:폭파한 뒤 그 주변을 다시 폭파했을 때, 작은 폭파 반경이 한 번 매우 커진 것으로 보임.
- 사용자 추가 답변:최근 설치한 아이폰 앱에서 관찰했고, 실제 건물 픽셀이 넓게 사라진 쪽 같다고 답함(“1번 같아”). 관찰 플랫폼은0.5.53(63)으로 특정했으며, 실제 파괴 여부는 사용자 추정임. 후속 답변에서 압력 확산(expand) + 지면 파동(wave) 장착, 맵 공통으로 다리와 몸통 사이에서 관찰한다고 구체화함. 타수·업그레이드 레벨·당시 실기 이벤트는 미확인임.
- 조사 기준:CURRENT.json의 iPhone0.5.53(63), `qa/ios-destruction-midpoint-2026-11-07/project`와 해당 C++ 소스. 공개 웹 기록의 releaseCommit95d6c6d 원본도 대조함.

## 확인한 데이터 흐름

1. `world.gd:attack`은 매번 stats.bombRadius / bombPower의 숫자를 새 폭파 Dictionary에 넣음. `blast_unprofiled`가 그 radius를 로컬 숫자로 받아 `cut_at`과 blast 이벤트에 각각 전달함. 앞선 폭파의 반경을 더하거나 덮어쓰는 경로는 조사 범위에서 발견하지 못함.
2. `PPWorldKernel::cut`은 각 픽셀 현재 좌표와 클릭점 사이 거리 <= radius인 것만 직접 제거함. `PPWorldKernel::blast`는 별도의 stats.blastReach 안 조각/움직이는 모래에 힘을 줌. 직접 제거 반경과 밀치는 범위를 구분해야 함.
3. `skill_vfx.gd:process_events/_push`는 폭파 이벤트를 복사함. 기본 blast/shockwave/smoke는 전달된 radius로 그려지며, 이웃 공격의 반경을 누적하지 않음. 스프라이트 자체의 프레임 확장/이벤트 겹침은 실기 화면 확인이 필요함.
4. `impact_physics.gd:blast_halo_unprofiled`는 직접 제거 원보다 큰 범위에 별도 결합 손상을 줌. force=clamp((power/efficiency−1)*4,0,5), reach=radius+2+force*1.6. 같은 판·동일 장비라면 이 reach 자체도 클릭마다 고정임.
5. `PPEffectKernel::halo_bonds`는 world.bonds의 기존 손상 old에 added를 더함. `PPPixelKernel::groups`는 결합 손상이1에 도달하면 연결을 끊음. 따라서 이웃 클릭의 halo가 겹치는 곳은 첫 공격에서 버티다가 후속 공격에서 넓게 분리될 수 있음. 이것은 기본 반경 증가와 별도이며, 제보가 실제 넓은 파괴라면 우선 확인할 경로임.
6. 분리 후16픽셀 이하의 연결 없는 작은 조각은 모래가 됨. 몸체가18개를 넘으면 큰 순으로18개를 남기고 나머지 조각 전체를 모래로 바꾸는 기존 처리도 있음. 이 추가 전환은 직접 제거 원으로 제한하지 않음. 따라서 직접 제거 count와 전체 새 모래 수를 같다고 보면 안 됨.
7. Pressure Bloom(압력 확산) 장착 시 유효 공격5회마다(해당 기본 구간 Lv5는4회) 반경2→11의 별도 필드가1.6초간 생김. 후속 폭파는3타마다 반경2.5의 추가 폭파를 주변에 배치함. 장착/타수 확인 없이 이들을 원인으로 단정할 수 없음.

## 최근 변경과의 관계

직접 폭파 반경, 패시브 처리와 VFX는0.5.53 중간값 변경에서 손대지 않았음. skill_physics.gd / presentation/skill_vfx.gd / impact_physics.gd는 공개 웹 releaseCommit95d6c6d의 소스와 byte-identical임. 직전 변경은 충돌 반응·연쇄·낙하 내부 균열5개 수치이며, 폭파 radius를 순간 증폭하는 코드는 추가하지 않았음.

## 다음 확인의 구분

- 기본 blast 이벤트의 radius가 달라지는지: 같은 업그레이드로 연속 공격 이벤트 radius 비교.
- radius는 같은데 직접 cut 후보만 원 밖인지: 픽셀 좌표·클릭점·거리와 radius 비교.
- 직접 제거는 정상인데 넓게 픽셀화되는지: blast-halo 결합 단절, fall/speed-fracture, chain-impact, 작은 파편 전환,18몸체 초과 전환을 분리.
- 이펙트만 커지는지: 기본 blast와 expand/echo/relay/orbital의 이벤트 종류·반경·동시 재생·카메라 줌 구분.

위는 향후 확인 항목이며 이번에 진단 코드를 추가하거나 게임을 실행한 결과가 아님. 소스 읽기와 파일 대조만 수행했고, 테스트·씬·시뮬레이션·브라우저·기기 앱 실행, 빌드/설치/배포는 하지 않았음. 버그 확정/수정 완료로 표시하지 않음.

##2026-11-08 · 실제 파괴 범위 제보 후 추가 조사

`world.gd:512~529`의18몸체 초과 분기를 별도로 확인했다. 작은16픽셀 이하 조각 처리와 달리, 초과 분기는 남길18개를 크기순으로 고른 뒤 나머지 조각의 모든 픽셀을 모래로 전환한다. 그 분기에는 픽셀 수 상한·폭파점 거리/반경·hinge/구조 연결 보호 조건이 없다. 따라서 여러 공격으로 조각 수가 문턱을 넘는 시점에는 직접 폭파 원 밖의 큰 덩어리도 통째로 픽셀화될 수 있다. 이 코드 특성은 확인했지만 제보 장면에서 실제 발동했다는 로그는 없다. 성능 한도를 단순히 높이는 수정이나 누적 균열 삭제는 하지 않았다.

기존 run_journal은 profileStart(맵·업그레이드·장착)와 주기적인 run.snapshot(픽셀 총량·배터리·공격 수·장착 상태)을 보관한다. 그러나 클릭별 중심/반경·직접 제거량·몸체 초과 전환량·픽셀화 원인을 저장하지 않아 기존 기록만으로 해당 순간의 원인을 확정할 수 없다. 후속 계측이 필요하다면 기본 공격 radius·직접 cut 수와, 누적 균열/충돌/작은 파편/18몸체 초과 전환의 수량을 구분해야 한다. 현재 원인 후보는 누적 균열 문턱과 몸체 초과 전환이며, 스킬 장착 정보 전에는 패시브도 완전히 배제하지 않는다.

추가 검증 역시 소스 읽기/텍스트 조건 대조만 수행했다. 게임 실행·재현·진단 코드 추가·앱 재설치는 하지 않았다.

##2026-11-08 · 장착 조합·연결부 조건으로 압력 전파 경로 특정

사용자 답변: **압력 확산 + 지면 파동**, 특정 맵에 한정하지 않으며 **다리와 몸통 사이**를 공격할 때 중요하게 관찰됨. 이 조건에서는 아래 공통 압력 경로가 기존 누적 halo 손상/18몸체 초과 후보보다 직접적인 설명임. 실기 장면에서의 호출 로그를 확보한 것은 아님.

1. `skill_physics.gd:338~360`의 `_pressure`는 스킬 영역 안의 후보 몸체를 고른 뒤, 몸체의 가장 가까운 픽셀에 local radius4의 압력을 적용함. 입력 재료는 그 몸체 **전체**임. 압력 확산 필드와 지면 파동 pulse가 모두 이 경로를 사용함.
2. `impact_physics.gd:26`은 `piece != null and strength >= 1.25`일 때 C++의 propagates를 켬. 아직 고정된 구조물은 piece=null이고, 다리 연결을 잃어 분리된 몸통은 piece!=null이 될 수 있으므로 같은 연결부 주변 공격에서 적용 방식이 달라짐.
3. `effect_kernel.cpp:77~83`은 접촉점에서 몸체 중심을 향한 축을 잡고, 전체 몸체 재료를 훑어 길이 reach를 산출함.
4. 같은 파일108~118의 on 조건에는 깊이/거리의 상한이 없고, `distance >= radius && !on`이므로 균열선에 걸린 결합은 local radius4 밖에서도 처리됨. 이것은 몸통 전체에 균일한 피해를 주는 코드가 아니라, **몸체 안쪽 끝까지 한 줄의 인위적인 균열을 강하게 보내는 보정**임.
5. 압력 확산의 기본 pressure는1.5, 지면 파동은1.6으로 처음부터1.25 문턱 이상임. 전파 감쇠는 끝에서도70%가 남고 결합 저항은 최대1.15임. 가장 약한 기본값/가장 강한 결합에서도 증분은 각각 `1.5*1.1*0.7/1.15=1.00435`, `1.6*1.1*0.7/1.15=1.07130`이므로, 코드의 균열선 판정에 걸린 연결은 기존 손상이0이어도 한 pulse에1까지 올라가 끊어질 수 있음. 전체 몸통 길이에 비례한 에너지 예산·질량 감쇠는 이 전파 계산에 없음.
6. 그 후 `_rebuild`와 기존 충돌/모래 전환이 이어지므로 직접 폭파 원이 같아도 넓은 몸통이 갑자기 쪼개지고 픽셀화될 수 있음.18몸체 초과 변환이 겹치면 그 결과를 더 키울 수 있지만, 이번 제보의 선행 조건은 압력 전파 쪽이 더 잘 맞음.

동일한 전파 보정이 보존된 Phaser `src/impact-world.js:126~151`에도 존재함. 이번 중간값 조절에서 새로 생긴 Godot 전용 코드로 보지는 않음. 직전 충돌/낙하5개 수치 조절은 이 압력 전파 식에 적용되지 않음.

정적 근거는 BUG-015-pressure-path-evidence.json. 실제 엔진이나 게임 함수를 호출하지 않고 소스 호출 관계와 상수의 산술 범위만 확인했음. 수정 방향은 압력 스킬의 추가 균열에도 명시적인 거리 한도/감쇠를 적용하고, 기존 낙하·물리 충돌 연쇄는 분리해 유지하는 것임. 구현·빌드·설치·배포는 아직 하지 않음.
