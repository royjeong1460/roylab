# BUG-003 · Safari 무료 웹 첫 로딩 지연

- 제보일: 2026-11-02.
- 대상: https://roylab.pages.dev/planet-patchup/play/ , Godot0.5.34-free.
- 사용자 관찰: Safari에서 처음 열 때 오래 걸림. 재방문 지연이나 로딩 실패로 제보한 것은 아님.
- 상태: 음악 리소스 축소 수정·빌드 완료 · 무료 웹 배포 진행 · 사용자 확인 대기. Safari 실제 재현/시간 측정은 하지 않음.

## 확인한 다운로드 부담과 조사 범위

최초 필수 파일은 WASM9,469,248바이트+PCK16,202,232바이트, 합계25,671,480바이트다. PCK의 WAV 음악 하나가14,412,639바이트를 차지하며 음악만 gzip해도12,651,461바이트다. 원본81.702초/44.1kHz/스테레오 음원을 압축 없이 가져오는 설정이 주요 다운로드 부담이다. 엔진과 전체 PCK는 모두 준비돼야 시작하므로 음악이 시작 화면 진입 전에 필요하다.

Mac의 정적HTTP에서 PCK는200/TTFB0.151초/총1.637초였다. 이 값은 iPhone/Safari 로딩 시간이 아니며 서버 고유 지연이나 Safari 초기화 비용을 단정하지 않는다. 첫 실행은 WASM 초기화·압축해제도 포함한다. v0.5.9와 엔진 바이트가 같고 v34 PCK 증가는55,044바이트뿐이므로 이번 UI 변경으로 대규모 파일이 새로 늘어난 것은 아니다.

## 이전 제안 · 적용하지 않음

무료 웹 배경음악의 import 압축만 QOA로 적용하는 작은 변경부터 검토한다. 원본 WAV·곡·프레임 수·스테레오·44.1kHz와 기존 루프/음량 코드는 보존한다. 효과음·물리·저장·분석·무료 해금 범위는 변경하지 않는다. 새 패키지 크기와 실제 포함 내용을 정적으로 확인한 뒤 사용자에게 Safari 체감을 확인받는다. 사용자는 “화질·음질 변경 없이 다른 원인부터 조사”를 선택했다. QOA 등 손실 압축 제안은 승인되지 않았고 제품에는 적용하지 않는다.

[Godot4.6음원 가져오기 안내](https://docs.godotengine.org/en/4.6/tutorials/assets_pipeline/importing_audio_samples.html)는 WAV 원본을 유지한 import 압축을 지원하고, QOA의 용량·품질·CPU 절충을 설명한다. 압축은 손실 압축이므로 음질 동일·무부하를 보장하지 않으며 실제 청취/발열 확인은 사용자 담당이다.

## 무손실 조사 · 2026-11-02

- 시작 HTML은 Mac 정적HTTP에서200/TTFB0.172초/총0.176초/리다이렉트0, 엔진은200/TTFB0.173초/총1.199초/리다이렉트0이다. Mac에서 서버의 긴 대기는 관찰되지 않았지만, 사용자 Safari 네트워크/초기화 속도를 대신하지 않는다.
- 저장 스냅샷 확인→PPFreeWebReady 완료 이후 엔진·게임 다운로드를 시작한다. 구버전 저장 잠금 경합 시 최대10초 타임아웃이 있으며, 모든 사용자에게 고정10초 지연이 있는 것은 아니다. 다운로드와 저장 확인을 겹치는 개선을 검토할 수 있으나, 엔진 시작과 저장 쓰기는 기존 안전한 준비 경계를 지켜야 한다.
- 엔진과 PCK 다운로드는 Promise.all로 병행한다. 엔진은 DecompressionStream→tracked Response→WebAssembly.instantiateStreaming 경로이며, gzip 때문에 무조건 전체 WASM 수신 후 컴파일한다고 볼 근거는 없다. PCK는 원래 Godot 경로에서 전체19,664,732바이트를 받은 뒤 메모리 파일시스템에 복사한다.
- 시작 행성의64×64랜드마크6개에2개 상태 변형을 생성하는49,152픽셀 반복이 있다. 이미지 수정 없이 이전 계산을 재사용할 여지는 있으나, 이 처리의 실제 Safari 소요 시간은 측정하지 않았다.
- 같은 엔진 바이트라도 콘텐츠 업데이트 때 URL이 달라진다. 안정된 엔진 캐시 주소는 업데이트 후 재방문에는 도움 될 수 있지만, 완전 첫 방문의 원인 해결과는 구분한다.
- 화질·음질을 유지하는 Brotli 무손실 재포장 비교에서25,671,480→20,007,802바이트(22.06%감소), 완전 동일 복원을 확인했다. 배포·전송 방식 변경·브라우저 실행 없음.

## 최종 조사 정리

사용자가2026-11-02에 “조사 결과만 정리”를 선택했다. 개선안을 제품에 적용하지 않으며 버그를 완료 처리하지 않는다. 상세 결과는 [첫 로딩 조사](../qa/2026-11-02-free-web-cold-load/README.md)에 기록했다.


## 음악 리소스 수정 · 2026-11-03

사용자는 이후 “음악부터 확 줄이자”, “음악을 줄일수 없나? 리소스 말야”라고 범위를 구체화했다. 브라우저/M4A 재생 연결부 변경은 적용하지 않고, 기존 Godot 재생 방식 안에서 음악 파일만 압축한다. 이전 조사만 정리하라는 요청 이후 승인된 별도 수정이다.

- 현재 v5 원본 WAV에서 직접 MP3 192kb/s·44.1kHz·스테레오로 변환했다. 원본14,412,300바이트를 보존하고 배포용 MP3는1,962,361바이트로86.38% 줄였다. 음량 보정·길이 편집·리믹스 없음. 손실 압축이며 파형·청감 동일을 주장하지 않는다.
- 원본과 MP3의 유효 프레임은3,603,064개, 길이는81.7021315초로 같다. native AudioStreamMP3에 loop=true, loop_offset=0을 설정했다. 기존 AudioStreamPlayer·음량·음악 토글·일시정지·브라우저 연결부·효과음 코드는 변경하지 않았다.
- 카탈로그의 음악 경로만 MP3로 교체하고, 보존한 원본 WAV는 무료 export에서 제외했다. 무료 빌더는 MP3 실제 바이트·반복 import 설정·원본 WAV 리소스 제외를 확인한다.
- 새 무료0.5.34 자산 묶음: `free-0534-c5a7a90dd912`. gzip PCK16,202,232→5,432,455바이트(66.47%감소). 동일 엔진9,469,248바이트를 합친 주요 다운로드는25,671,480→14,901,703바이트(41.95%감소). HTML·JS 등의 부가 파일을 포함한 전체 방문 전송량이나 실제 iPhone 로딩 시간 측정치는 아니다.
- 정적 패키지290항목의 경계·MD5를 확인했다. 기존 공유285항목과 모든 `.gdc` 바이트가 같고 무료8맵·3스킬이 유지된다. 달라진7경로는 음악 리소스·카탈로그·UID 캐시·생성 장면이다. 생성 장면은 단일 루트의 `_bundled.node_ids[0]` 4바이트만 다르며 장면 원본은 동일하다. WAV는 패키지에서 제외됐고 UID 캐시에 과거 경로 문자열만 남는다.
- Godot import/check-only/export, Vite 무료 빌드, Next 정적 빌드 모두 최종 종료0. 첫 Next 시도는 외부를 가리키는 로컬 node_modules 심볼릭 링크 때문에 실패했고, 무시되는 의존성 폴더를 실제 디렉터리로 복제해 재빌드했다. 게임·Next 코드/설정 변경 없음. 독립 소스·패키지 리뷰에서 차단 사항 없음.
- 검증 근거: [음악 리소스 QA](../qa/2026-11-03-free-web-mp3/README.md), [정적 패키지 결과](../qa/2026-11-03-free-web-mp3/package-verification.json), [독립 리뷰](../qa/2026-11-03-free-web-mp3/source-review.md).

### 남은 사용자 확인

iPhone Safari 첫 로딩 체감, 음악 품질·반복 경계·음악 토글·일시정지는 사용자 확인 대기다. 에이전트는 게임·브라우저·기기·오디오를 실행하지 않았고 저장 데이터에 접근하지 않았다. 유료 앱은 이번 무료 웹 리소스 수정 범위에 포함하지 않는다. 사용자가 완료를 확인하기 전에는 BUG-003을 완료 처리하지 않는다.
