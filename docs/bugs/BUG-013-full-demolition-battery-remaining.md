# BUG-013 · 전체 파괴 후 배터리가 남으면 종료되지 않음

접수: 2026-11-07. 상태: 2026-11-11 재접수 · 숨은 잔여 조각 조사 및 로컬 경계 보정 사용자 확인 대기.

## 제보와 원인

사용자는 “100프로인데 배터리가 남으면 그대로 멈춰있어”라고 제보했다. 현재 공용 RunSession은 배터리 소진 때만 working → finishing으로 넘어간다. 픽셀화된 모든 ID가 잔해/회수 목록에 있어도 전환하지 않는다. 기본 폭파는 정적 건물과 몸체만 공격 대상으로 인정하므로 모두 부서진 뒤에는 빈 폭파로 남은 배터리를 쓸 수도 없다. 실제 기기 상태를 읽거나 재현한 것은 아니다.

## 수정

공용 campaign/run_session.gd의 종료 점검을 배터리 소진 또는 전체 픽셀화로 확장한다. 초기 총 픽셀 수가 양수이며 잔해 수+이미 회수된 ID 수가 초기 총수 이상인지 정수로 판정한다. 화면에 반올림된 퍼센트, 남은 조각 수나 지형은 조건으로 사용하지 않는다. 배열/딕셔너리의 size만 읽어 매 프레임 전체 픽셀을 탐색하지 않는다.

수집 준비·안정 대기·중앙 흡수·70/80/90/100% 축하·결과 페이드·정산·배터리 수치·스킬 위력은 기존 경로를 재사용한다. 튜토리얼·일반맵·보스 모두 같은 점검을 사용한다. 남은 배터리는 0으로 변경하지 않는다.

## 확인 범위

소스 추적에서 원인을 확인했다. 사용자 지침에 따라 게임 테스트·씬·브라우저·기기 앱은 실행하지 않는다. 컴파일·패키지·배포·설치 결과는 전달 기록에 추가한다. 런타임 수정 완료 판정은 사용자 확인 대기다.

사용자 확인: 배터리를 남긴 채 전량 파괴 → 자동 수집/100% 연출 → 결과; 일부만 파괴한 상태에서는 계속 공격 가능; 배터리 0에서는 기존 수집; 잠시 일시정지 후 복귀해도 종료/보상 중복 없음.

## 2026-11-11 · 1-3, 배터리41% 상태에서 종료되지 않음

사용자는 방금 설치한 아이폰0.5.58에서 블록을 모두 깬 것으로 보이지만 배터리41% 상태로 종료되지 않는다고 제보했다. 흰 테두리 잔재도 보이지 않았고, 놓친 것이 있는지 확인하려고 사용한 위성도 보이지 않았다고 답했다.

해당 앱에 저장된 최신 사용자 플레이 기록을 읽기 전용으로 가져왔다. mapId=arch-3-arch-quarter-v2, total1898, grains1870, chunks28, static0, collected0, phaseworking. 배터리81.6227766016838/201.622776601684=40.48%. 최근5개 샘플에서 동일한28픽셀이 조각 계층에 남았다.1898=1870+28로 집계 손실은 없다. 자동 종료가 되지 않는 직접 이유는28픽셀이 아직 수집 픽셀이 아닌 몸체로 남아 있기 때문이다.

기존 기록에는 개별 몸체 위치·화면/지형 안팎·렌더 상태가 없어, 그28픽셀이 왜 보이지 않는지는 확정하지 못했다. 위성 사용은1회 기록되어 있지만 대상 좌표와 실제 비행 위치는 옛 기록에 없다. 모래 가림, 화면 밖, 지형 아래, 유효하지 않은 좌표/렌더 문제 등을 사실로 단정하지 않는다.

[진단 후보·집계 근거](../qa/2026-11-11-finish-residue-trace/README.md): 남은 구조 픽셀64이하일 때만 기존5초/일시정지 journal 체크포인트에 좌표·가시성·연결 상태를 덧붙이고, 광역 스킬 발동 요청과 타깃을 최대16개 저장한다. 물리·정산·종료 조건을 변경하지 않는다. 현재 미정산 판이 업데이트로 사라지지 않도록, 사용자 정산/메뉴 복귀 후 설치한다. 원인 확정·기능 수정은 새 사용자 기록을 보고 결정한다.

사용자가 “해결한 거야? 로컬에서 다시 테스트”라고 요청해 진단 아이폰 설치를 보류했다. [별도 로컬 재현판](../qa/2026-11-11-finish-residue-trace/local-README.md)을127.0.0.1:8806에 준비했다. 해당 iPhone run의 profileStart 강화/장착/스킬/재화를 유지하고 UI선택만 지역0/1-3으로 두었다. 독립 저장 영역이며 기존8805/아이폰/공개웹은 변경하지 않는다. 사용자 재현 시 기존5초/일시정지 기록을 서버 records에 복사해 숨은 조각의 좌표를 분석한다. 빌드·정적HTTP만 확인했고, 문제가 해결됐다고 판정하지 않는다.

## 2026-11-11 · 로컬 재플레이와 경계 코드 확인

2026-11-11 사용자 로컬 재플레이는1-3에서1898/1898회수, chunks0/static0, 배터리117.622776601684를 남긴 채 정상 종료했다. 폭파7회·소닉1회·위성1회였으며 아이폰 실패 기록의 폭파10회와 동일한 입력 재현은 아니다. 이 결과로 간헐 오류가 해결됐거나 아이폰 전용이라고 판정하지 않는다.

로컬 소닉 발동 시 구조물 좌표 최상단은y=-29.740139칸이었다. native bounds는 실제 구조 픽셀의 최소y를 반환하므로 화면/논리맵 상단 밖으로 떠오르는 동작은 사용자 로그에서 관찰했다. 영구 이탈이 발생했다는 증거는 아니다.

현재 코드에는 바닥·좌우 충돌체와 CCD/속도 제한이 있지만 천장은 없고, 측면 벽의 높이와 바닥 두께는 유한하다. RigidBody가 실제 물리 영역을 벗어나거나 유효하지 않은 좌표가 됐을 때 복구/수집 픽셀로 전환하는 별도 경로는 없다. 따라서 카메라 바깥 비행과 물리 영역 이탈 가능성을 구분해 남긴다. 아이폰의 숨은28픽셀이 이탈했는지는 여전히 미확정이며, 조건부 이탈 복구는 제안만 하고 적용하지 않았다. ## 2026-11-11 · 맵 이탈 차단 로컬 후보

사용자는 조각이 맵 밖으로 사라져서는 안 된다고 정정했다. 기존 물리 벽 상단에 천장을 추가하고, 충돌체·힌지 적분을 뚫은 경우 몸체 전체를 같은 ID로 안쪽에 유지하는 보정을 로컬8806에 적용했다. 카메라 끝은 경계로 쓰지 않고 기존 하늘 여유 공간을 보존한다. 픽셀 수·스킬·파괴·정산 수치는 바꾸지 않았다. 최근 경계 보정은 journal에 기록한다.

[후보·검증·롤백](../qa/2026-11-11-local-boundary-guard/README.md). import/compile/export와 정적HTTP·해시는 확인했으며, 실제 경계 반응·물리 느낌·FPS는 사용자 확인 대기다. 공개 웹과 아이폰에는 이 후보를 반영하지 않았다. 원래 아이폰28픽셀의 위치 원인은 이 변경만으로 확정하거나 해결 판정하지 않는다.

사용자가 이후 “우선 업데이트 해줘 다”라고 승인하여 최신 배경0.5.60을 보존한 채 경계 보정을 공용 웹·아이폰으로 채택했다. 로컬 개인 프로필/진단UI는 제외했다. 아이폰0.5.61(71) 빌드·서명 확인 및 덮어 설치(sequence4676) 완료. 웹 배포와 정적HTTP 확인은 [전달 기록](../qa/2026-11-11-boundary-guard-release/delivery.json)을 따른다. 실제 경계 반응과 기존1-3간헐 문제는 사용자 확인 대기로 유지한다.
