## Important findings

No remaining finding. The following finding is retained as resolved history.

1. **FIXED.** **Engine script download failure leaves a blank screen without recovery guidance.**

   Location: `public/games/planet-patchup-free/index.html:110` and `:114`; generated by `demos/planet-patchup/scripts/build-godot-free.mjs:101-107`.

   What this is: The HTML loads the engine JavaScript synchronously, then immediately constructs `new Engine(GODOT_CONFIG)`. The visible startup/error handler is initialized later inside the IIFE.

   Problem: If the engine `.js` request fails (for example a failed network request), the script tag has no error handler. `Engine` is undefined and construction throws before `setStatusMode` or `displayFailureNotice` can run. The status overlay starts with `visibility: hidden`, while the separately loaded shell can still finish preparation and resolve readiness. The user sees an empty canvas instead of the requested startup/download error notice. The shell-module error handler only covers the shell module.

   Minimal fix: Generate an engine-script load error handler that shows a visible fatal reload message, and guard initialization when `Engine` is missing. Make the change in the builder, then regenerate the entry; do not hand-edit canonical generated HTML. Static inspection of the regenerated branch and the appropriate existing bundle/build check are sufficient for this review's boundary.

   If skipped: An engine download failure is indistinguishable from a stalled/blank game, with no useful recovery instruction.

2. **FIXED.** **New Godot events advertise the legacy balance version.**

   If skipped: Analysis using only the balance dimension mislabels this release.

## Strengths and complete-flow assessment

- **Canonical route and retained archive:** The route generator inserts `<base href="/games/planet-patchup-free/">` before relative resources in `/planet-patchup/play/`. The archive gets its own Phaser base and retained chunk/editor paths. The builder copies the old release once and adds new versioned output without deleting original chunks. Preview query redirects stay on the same origin and retain search/hash. The reviewed source does not alter paid/native code.
- **Startup and writer ownership:** The root readiness Promise is created before the shell module and is not replaced by the shell. The start wrapper waits on that Promise. The shell acquires the dedicated destination Web Lock before preparing and resolving, holds it for its lifetime, then reads original free slots/journals under their original lock. Missing/competing locks and snapshot errors have visible failure/recovery paths. The separate destination lock prevents two independent restored filesystems from becoming simultaneous profile writers.
- **Dedicated filesystem and bootstrap:** `persistentPaths` is overridden before the emitted engine's `startGame` updates its configuration and calls `init`. The emitted `initFS` Promise precedes main startup. `/userfs/PlanetPatchupGodotFreeWeb` matches the custom project directory. Journey setup reads the store before bridge bootstrap; the new profile remains in memory until an authorized transaction. Bootstrap runs before home/ready, and persistence-unavailable checks reject migration and all shared profile writes/imports.
- **Conservative migration:** Only exact free v1/v2 slot keys and the original free journal prefix are read. Raw strings are retained, archived before import, and never sent to analytics. Existing slots/recovery copies prevent automatic overwrite. Invalid/conflicting active legacy candidates block progression with recovery guidance; markers cannot suppress source/destination validation. Redundant verified import and the refund archive retain original ledgers and avoid repeating collection refunds. Filesystem sync is requested without claiming durable readback.
- **Physical and logical free scope:** The catalog, progression, start paths, purchases, equipment and profile validation share the eight-map/three-skill limits. Five other regions are empty locked previews. One passive and one active slot are enforced in both schema and loadout. The package's map path strings match the allowlist. The corrected frozen-baseline diff leaves automatic collection/shared physics unchanged, retaining unlimited numeric guards and historical costs. Restoration remains distinct normal records plus boss clear.
- **Filename rewriting and compression:** The package stem includes source hash and actual WASM/PCK bytes. HTML and exported JavaScript are rewritten to the final stem; loader resources are derived from that configured stem. The builder gzip-encodes only WASM/PCK, verifies lossless decompression, preserves original extensions and emits exact path-specific gzip/MIME/no-transform headers, including retained older generated versions. The current generated HTML, artifact filenames, and QA manifest agree.
- **Analytics/feedback lifecycle:** Stable run adapter identity satisfies the unchanged transport's equality guards. Frame snapshots are emitted at at most 2 Hz. Only a compact run/result/purchase payload is forwarded, not raw profiles/journals. Existing configuration, browser identity, opt-out and explicit-feedback semantics are reused. Feedback opens one modal, retains a callback, pauses/resumes according to prior engine state, retains failed answers and submission identity, and restores canvas focus. Page visibility and departure are wired to the transport.
- **Deployment integration:** Root `npm run build:game -- --free` routes to the Godot builder; ordinary site build regenerates routes then uses Next static export and checked-in public assets. Cloudflare does not need to run Godot. At the time of static inspection, final `out/` copies did not yet match the current public canonical entry, headers and versioned engine files; the coordinator had already reported the final Next rebuild in progress. Final output parity is a pending build/delivery gate, not a new source finding or a completed verification claim.

The earlier core-review documentation inventory finding is corrected: the implementation report now explicitly names the frozen 0.5.9 baseline. This review does not reopen the previously approved core/browser/storage work without a concrete new integration issue.
